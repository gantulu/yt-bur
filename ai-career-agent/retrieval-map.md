# GITHUB RETRIEVAL OPTIMIZATION

**Status:** LOCKED  
**Phase:** 14

## Purpose
Minimize unnecessary GitHub retrieval while ensuring every stage has the authoritative modules required to make a valid decision.

## Retrieval Principles

1. Start with `ai-career-agent/AGENT.md`.
2. Retrieve the smallest complete module set for the current stage.
3. Prefer exact repository paths over broad repository searches.
4. Do not retrieve downstream engines before their stage is active.
5. Retrieve validation rules at consequential decision boundaries.
6. Retrieve state/evidence modules when user-specific decisions are being made.
7. If a referenced module is missing, do not substitute model knowledge; use the failure contract.
8. Do not assume one retrieval call establishes repository-wide context.

## Universal Entry Bundle

Always begin with:

```text
ai-career-agent/AGENT.md
```

Add only the bundle required by the current stage.

## Reassessment Optimization

Use dependency-directed retrieval:

```text
NEW EVIDENCE
    ↓
Affected State
    ↓
Affected Engine
    ↓
Affected Downstream Decisions
    ↓
Validation
```

Do not rerun or retrieve unrelated stages.

## Failure and Fallback

If an exact path returns not found:

1. Verify the path once.
2. Check `AGENT.md` and this retrieval map for the canonical replacement.
3. If no replacement exists, mark the dependency missing.
4. Do not invent the missing module.

## Retrieval Efficiency Rules

- Read complete small modules when needed for deterministic rules.
- Avoid retrieving duplicate aggregate/legacy files when modular files are authoritative.
- Avoid loading all career/project/reference data during discovery.
- Avoid loading output contracts until a response contract is required.
- Avoid loading portfolio/execution modules before those stages.
- Retrieve `prompt.md` only when AI Creative Technologist domain details are specifically required; it remains immutable.

## Canonical Entry Sequence

```text
AGENT.md
→ current-stage bundle
→ minimum affected dependencies
→ validation-rules.md
→ output-contracts.md when presenting a contracted output
```
