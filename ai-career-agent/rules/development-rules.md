# DEVELOPMENT RULES

**Status:** LOCKED  
**Phase:** 8

## Mandatory Rules

1. Development begins from the selected career direction and current competency evidence.
2. Identify target capability before prescribing learning activity.
3. Calculate the meaningful gap between current and target capability.
4. Prioritize gaps by career impact, interest sustainability, and project relevance.
5. Use NOW, NEXT, LATER sequencing.
6. Prefer applied learning that produces evidence over passive consumption.
7. Every major development item should have an observable evidence target.
8. Do not prescribe a skill solely because it is popular or fashionable.
9. Do not treat course completion as proof of competency.
10. Do not create a development plan when the career direction is materially unresolved; resolve matching first.
11. Keep the plan small enough to execute.
12. Reassess priorities when new evidence, project results, goals, or constraints materially change.

## Priority Model

Prioritize using:

career impact + interest alignment + project relevance + evidence value

The model is qualitative unless a later version explicitly defines numeric scoring.

## NOW / NEXT / LATER

### NOW
Highest-value capability or evidence gap that should be addressed immediately.

### NEXT
Capability that becomes important after NOW evidence is produced.

### LATER
Useful capability with lower immediate career impact.

## Evidence Target

Each priority should define what would demonstrate progress, for example:
- completed workflow;
- working prototype;
- automation;
- agent;
- measurable result;
- documented project;
- validated user outcome.

The example itself is not proof; the actual result becomes evidence.
