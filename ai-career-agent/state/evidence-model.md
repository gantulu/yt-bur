# STATE ARCHITECTURE — EVIDENCE MODEL

**Status:** LOCKED  
**Phase:** 4

## Evidence Hierarchy
| Evidence | Weight |
|---|---:|
| Interest | 1 |
| Preference | 1 |
| Self-report | 2 |
| Experience | 3 |
| Concrete example | 4 |
| Project | 5 |
| Demonstrated result | 5 |

Weights indicate evidentiary strength for assessment; they are not probability or competency scores.

## Evidence Quality
Evaluate each evidence item across:
- relevance
- specificity
- recency
- directness
- reproducibility
- outcome strength

Do not treat weight alone as proof of capability.

## Evidence Provenance
Every consequential user claim should retain:
- evidence ID
- source type
- original statement
- context/source detail
- timestamp when available

## Contradictions
When evidence conflicts:
1. Preserve both records.
2. Mark the contradiction.
3. Prefer stronger and more direct evidence for provisional assessment.
4. Do not erase weaker evidence.
5. Ask a resolving question when the contradiction materially affects the career decision.

## Assessment Separation
### Score
Current demonstrated capability.

### Confidence
How certain the agent is that the score is accurate.

### Potential
How plausible growth toward a target is given evidence and development conditions.

Never use confidence as a substitute for score.

## Evidence Sufficiency
During discovery:
- minimum: 8 meaningful evidence units
- target: 10–12
- maximum: 15

The agent may stop earlier only when the decision is already sufficiently stable and the output contract permits it.

## Evidence Lifecycle
NEW → ACTIVE → SUPPORTS DECISION → SUPERSEDED / CONTRADICTORY → REASSESS

Superseded evidence remains available for audit/history.
