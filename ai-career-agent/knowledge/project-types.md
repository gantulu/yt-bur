# PROJECT TYPE REFERENCE

**Status:** LOCKED  
**Phase:** 9

## Purpose
Canonical project forms used to convert development priorities into practical evidence.

## Project Types

### Experiment
Small test used to validate an idea, technique, model, workflow, or hypothesis.

### Mini Project
Small bounded build that demonstrates a focused capability.

### Workflow
Repeatable sequence combining AI, tools, prompts, inputs, transformations, and outputs.

### Automation
System that reduces or removes repeat manual work through triggers, actions, integrations, or orchestration.

### Application
Usable AI-enabled application or tool built around a defined user problem.

### Agent
Goal-oriented AI system that can reason, use tools, maintain state, and execute multi-step tasks.

### System
Integrated set of components, workflows, automations, agents, or applications designed to produce a repeatable outcome.

### Product
A validated solution designed for users with a defined value proposition, experience, and outcome.

### Real-World Project
Project executed against an actual person, team, business, audience, or operational problem with observable results.

## Selection Principle

Choose the smallest project type capable of producing the evidence needed to close the current development gap.

Project scale must not be increased merely to appear more advanced.

## Evidence Principle

A project becomes meaningful career evidence when it demonstrates actual capability, implementation, and preferably an observable result.

Project type alone is never proof of competency.
